## Lưu ý cho agent sau

- **Cách chống dương tính giả (quan trọng)**: trước khi quét link, `strip_code()` thay **toàn bộ** dòng nằm trong fenced code (``` ``` ``` hoặc `~~~`, mở/đóng cùng loại ký tự, đóng phải dài hơn hoặc bằng lúc mở và không còn ký tự khác trên dòng) bằng chuỗi rỗng, và `strip_inline_code()` thay mỗi code span `` `...` `` (hỗ trợ cả ` ``...`` `) bằng dấu cách **đúng độ dài**. Nhờ giữ nguyên số dòng và offset nên số dòng báo lỗi vẫn khớp file thật. Đừng bỏ bước này: 3 link `0001-use-nextjs.md`, `0002-postgres-over-mongo.md`, `0003-rest-over-graphql.md` của skill `architecture-decision-records` nằm trong fence ```` ```markdown ```` (dòng 109-117) và sẽ bị báo gãy oan nếu quét thẳng.
- **Bẫy đã gặp**: `Path.write_text()` trong test không nhận `newline=` trên Python <3.10 nên test dùng `write_bytes()` để số dòng không bị đổi theo CRLF của Windows.
- **Quy ước đang áp dụng**: link ảnh (`![alt](src)`) bị bỏ qua có chủ đích; target có `#anchor` được cắt phần fragment trước khi kiểm file; target `http:`/`mailto:`/`/tuyệt đối`/`{...}`/kết thúc bằng `/` đều bỏ qua.
- **File dễ vỡ**: `scripts/check-skills.py` là file dùng chung cho CI; nếu cần đổi ngưỡng 500 dòng thì chỉ sửa hằng `MAX_SKILL_LINES` (test đang khẳng định chuỗi `500` và `501`).
- **Chưa xác minh**: script chưa chạy trên macOS/Linux thật; regex không phụ thuộc đường dẫn nên nhiều khả năng giữ nguyên hành vi, nhưng `(d / local_target).exists()` phân biệt hoa/thường trên Linux — link sai hoa/thường sẽ bị báo ở Linux mà không báo ở Windows.
